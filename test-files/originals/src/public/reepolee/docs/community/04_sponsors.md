# Sponsors

<a name="introduction"></a>

## Introduction

Reepolee is open source and free to use, with no plans to change that. It's also the result of substantial engineering work — the framework, the documentation, the tooling, the maintenance — that has to be paid for somehow. Sponsors are how that adds up.

This page covers who currently funds the project, how to sponsor as an individual or company, and what sponsoring actually does.

<a name="primary-funder"></a>

## Primary Funder

Reepolee is built and maintained by [Reepolee](https://www.reepolee.com), a small software company that uses Reepolee for client work and product development. Reepolee underwrites the framework's core development time — the code in `lib/`, the generator, the documentation site, the VSCode extension. Without that, the rest of the funding model wouldn't work.

If you're hiring a team to build a Reepolee application and want the people who wrote the framework, [Reepolee takes engagements directly](mailto:hello@reepolee.com). Project work funds open-source work; the two are deliberately tied together.

<a name="how-to-sponsor"></a>

## How to Sponsor

For individuals and organisations that benefit from Reepolee and want to contribute back financially, the path is GitHub Sponsors:

[github.com/sponsors/reepolee](https://github.com/sponsors/reepolee)

We accept one-time and recurring sponsorships, both at any amount. Tiers exist mostly to make the form easier to fill in — the difference between "$10/mo" and "$15/mo" is not a meaningfully different relationship with the project.

For companies that need invoices, custom contracts, or larger commitments, contact us directly at hello@reepolee.com. We can structure something appropriate for your accounting and procurement processes.

<a name="what-sponsorship-funds"></a>

## What Sponsorship Funds

Three things, roughly in order:

- **Framework maintenance** — bug fixes, security patches, Bun-version compatibility, dependency upgrades on the dev tooling. This is the unglamorous-but-essential layer; most sponsorship goes here first.
- **New features and major work** — the items on [the Roadmap](/community/roadmap). Sponsorship doesn't buy roadmap priority directly, but it does fund the time to work on roadmap items. More sustained funding means more time for substantial improvements.
- **Documentation** — keeping these docs current as the framework evolves, expanding coverage, writing new recipes. Documentation work doesn't pay for itself in any project, so external funding is what keeps it from falling behind.

Sponsorship money doesn't go to individual contributors who send PRs — that's volunteer work and stays volunteer work. The sponsorship pays Reepolee to keep the framework, docs, and ecosystem in shape; volunteer contributions are credited on the contributor graph and the README, but not paid.

<a name="sponsor-tiers"></a>

## Sponsor Tiers

GitHub Sponsors lists a few tiers. The differences are mostly cosmetic:

| Tier           | Per month | What you get                                                                                                           |
| -------------- | --------- | ---------------------------------------------------------------------------------------------------------------------- |
| **Supporter**  | $5        | Listed in the sponsors section of the docs site (with permission).                                                     |
| **Backer**     | $25       | Above + a monthly digest email of what shipped.                                                                        |
| **Sponsor**    | $100      | Above + your logo in the sponsors section + a quarterly call with a maintainer.                                        |
| **Enterprise** | $500+     | Above + named contact for issues, priority on PR reviews for your team's contributions, optional roadmap consultation. |

Custom tiers and arrangements are possible. The shape of the relationship matters more than the dollar amount — a $50/month commitment from a company that uses Reepolee heavily and gives concrete feedback is more valuable than a one-time $5,000 donation that we never hear from again.

<a name="non-financial-support"></a>

## Non-Financial Support

If sponsorship isn't an option, there are other ways to support the project:

- **Use Reepolee on real projects.** Real-world use is what surfaces the bugs, design rough edges, and documentation gaps that move the project forward. A sponsor with a real production deployment that talks to us about what's hard is invaluable; a $100/mo sponsor that never engages is purely financial.
- **Write about it.** Blog posts, conference talks, tutorial videos, comparisons with other frameworks — they help people who haven't found Reepolee yet decide whether to try it. We'll happily share your work via the changelog and on social.
- **Contribute** — see [Contributing](/community/contributing).
- **Answer questions in Discussions.** A community where people get answers within hours is one where new users stick around. Established users who help newcomers compound the project's reach.

The framework needs both money and engagement to grow well. Either or both is welcome.

<a name="why-not-vc-funded"></a>

## Why Not VC-Funded

A common question: why is Reepolee a sponsorship-funded open-source project rather than a venture-backed company?

The short answer: the trade-offs of venture funding (growth pressure, exit timelines, the need to capture value commercially) conflict with what makes Reepolee useful (longevity, no dependency on the funder's continued existence, no premium tier behind a paywall). A framework that has to grow 10× a year to satisfy investors is a framework that ends up doing things that don't help the people using it.

The Reepolee + sponsorship model isn't immune to going wrong, but it doesn't have the same structural pressures. As long as Reepolee exists, Reepolee's core is funded. As long as the sponsorship layer exists, it can grow beyond what one company can fund alone. If both go away, the open-source code keeps working in every project that's already using it — which is the property the whole project is shaped around.
